# Finish activation using your existing accounts

The app is built and the preview uses an actual captured Riva Terra inventory. Saving user data, building historical records, unattended daily checks, email delivery and a permanent URL require account configuration. A preview is not an active tracking service.

1. Sign in to Supabase. Create a separate **Free** project named Rental Watch, or select an existing empty project intended for this app. Choose a nearby region. Enter and keep its database password yourself; do not paste it into chat.
2. Run `supabase/migrations/001_initial.sql` followed by `002_tracking_controls.sql` in that project's SQL editor. They create the tables, owner-only policies and worker functions. If you already ran the first migration, only run the second. Do not run either against an unrelated application database.
3. In Supabase Authentication, enable email/password. Configure the final Site URL and redirect URL allowlist. Production account emails need an SMTP sender. Test sign-up, confirmation and password recovery on the final origin.
4. Put the source-only project in a new **private** GitHub repository with `package.json` at the root. Configure Actions repository secrets `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`, and variables `INGESTION_ALLOWED_HOSTS=www.equityapartments.com` and `APP_URL=<final-app-origin>`. The worker key has elevated database access; only store it in this private worker secret, never in client code or a public environment variable. In-app alerts work without Resend. Email is optional and needs its own provider key and verified sender.
5. Import the repository into Vercel (personal/non-commercial Hobby) or another commercial-compatible Next.js host. Set **only** `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` for the web app. Never add the service-role key to the client or to `NEXT_PUBLIC_*`. Build with `pnpm build` and start with `pnpm start` if your host requires a start command.
6. Add the final URL to Supabase's auth redirect allowlist. Sign in to Rental Watch, create a group, paste the Riva Terra source URL, and manually dispatch “Daily rental check” under GitHub Actions. Its first successful run should inspect 17 units if today's inventory is unchanged; source inventory can legitimately change later.
7. Select “1 bedroom” without a size or floorplan filter to include **every** one-bedroom size. Optional filters narrow the pool only when you choose them. Sizes stay exact: 726 is never merged into 700 or 730. Default alert settings create in-app notifications for subsequent changes.
8. Dispatch another permitted check later and confirm two snapshots exist. The daily workflow then runs automatically. Confirm failure states, alerts, auth and account isolation before inviting users. Do not create artificial price changes in the real source to test alerts; the automated tests use isolated fixtures.
9. Set a blocking GitHub Actions budget to prevent paid overages, remain on free database and hosting plans, and review COSTS.md. Link the hosted URL from your own website, or add a subdomain through your hosting dashboard and DNS provider.

Local connection check: after storing your settings in ignored `.env.local` (public web settings) and `.env.worker` (worker secrets), run `pnpm doctor`. It logs only whether each setting/table is ready, never secret values. This cannot prove that scheduling, SMTP or live source extraction work; verify the first hosted worker run.

Any unresolved sign-in, project configuration, secret transfer or DNS step requires your participation or authorization. Until those are done, the status remains **not activated**, even though the local app builds and tests pass.
